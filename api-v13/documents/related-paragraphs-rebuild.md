## 1. 业务逻辑现状

### 1.1 这张表做什么

给定一个段落 `(book, para)`，找出与它有注释关系的段落（mūla ← aṭṭhakathā ← ṭīkā）。

匹配键是 `(book_name, cs_para)`：CS 版 html 里，根本书的段落锚点是 `<a name="para4">`，
义注、复注在注释该段处放 `<a name="para4_dn1">`。**相同 book_name + 相同段号即互为注释**。
`book_id`（= `book_titles.sn`）只用来输出书名，不参与匹配。

```
wbw_templates (.ctl. 锚点) ──(早年某脚本，已不可考)──▶ cs6_para.csv
    book,para,album,begin,end（一行一个 pali_texts 段落）
        │  UpgradeRelatedParagraph：begin..end 展开成多行
        ▼
related_paragraphs (book, para, book_id, cs_para, book_name)  631,838 行，2023-06 导入
```

### 1.2 消费者

| 消费者 | 用法 | 改数据的影响 |
| --- | --- | --- |
| `GET /v2/related-paragraph`（`RelatedParagraphController@index`） | v4 `components/corpus/RelatedPara.tsx`、**v6 `components/related-para/RelatedPara.tsx` 仍在调**、插件 `wikipali related` | 响应形状不变（不输出 book_name），只是结果变对 |
| `GET /v3/tipitaka-related-paragraphs`（+`/aggregate`） | 插件 `related-cs`、`note-context <book_name> <cs_para>` | 有回绕的书重编号后，**手输的 cs_para 不再是印本章内段号** |
| `GET /v2/para-info`（`ParaInfoController`） | 段落附带 `book_name` / `cs_para` | 值变 |
| `export:mobile-heading`（`ExportMobileHeading`） | mobile 离线库 `pali_text(book_name, cs_para)` 索引 | 重导即可 |
| `upgrade:sys.commentary`（`UpgradeSystemCommentary`） | 按 `book_name\|cs_para` 为单元生成 AI 注释，也是续跑游标 | 续跑游标会变；产物落在句子号上，不受影响（不处理） |
| `init:commentary`（`InitCommentary`） | `p_number = book_name-para` | 同上 |

查询细节：取锚点时 `where(book, para)->where(cs_para > 0)->first()`——一个段落展开成多行
（区间 `para5-7`）时只用其中一行（无 order by，实际是 id 最小的 begin），所以区间段落
从本段出发只能查到 begin 那个号的关联。不影响本次重建，记一笔。

### 1.3 现命令 `UpgradeRelatedParagraph` 的问题

1. **数据源 cs6_para.csv 被 Excel 打开保存过**：`4-5` 这类区间被存成日期序列号
   （`43926` = 2020-04-05）。现表 **942 行** `cs_para > 40000`，而且不同书里同一个
   「日期」会互相配上（例如所有 `4-5` 都变 43926，跨书串段）。
2. **缩写区间导入时空转丢段**：csv 原样保留了 `380,1`（源标记 `para380-1` = 380–381），
   `for ($i = 380; $i <= 1; $i++)` 一圈不进，**该段落一行都没有**。全库约 3,600 段。
3. **`{book}` 参数是坏的**：过滤只作用于读 csv，但 `RelatedParagraph::where('book','>',0)->delete()`
   先把整张表删了。带参数跑一次 = 只剩一本书。
4. 63 万行逐行 `save()`，慢；无事务，中途失败表就是半张。
5. 段落沿用无边界：一本书（`book_titles.sn`）结束后若下一本没有锚点，沿用上一本最后的
   cs 值（前作 E8：book 207 kaṅkhāvitaraṇī 1,499 段全被写成 cs=75）。

### 2.3 方案评估

**结论：方案可行，而且比前作的路线更适合「一个一个解决」。** 理由与需要补上的几点：

1. **wbw_templates 足以做唯一数据源。** 锚点 100% 可解析（前作 MarkerParser 实测零 unknown），
   P1/P2/P3/P7 这四类占现表错误的绝大多数，都只是规则问题，重建即消失。cs6_para.csv 只留作
   对照基线，命令不再读它。
2. **补丁是必须的，而且只能是补丁。** P4、P5、P6、P9 的信息在 wbw 里根本没有，或者
   需要读巴利文才能判定。前作尝试用「两侧每章 max(cs) 序列比对」自动加后缀，结果 5 个
   book_name 整名回滚、20 个置信不足——自动规则判不准的地方，显式补丁比启发式更可审、
   更可回退。
3. **回绕改 cs_para，不改 book_name。** book_name 是书的身份，插件、mobile 离线库、
   AI 注释游标都拿它当书名用；给它加章后缀会把一本书拆成几十个「书」，所有按书名
   聚合、列举的地方都得跟着认后缀。改 cs_para 则 book_name 保持干净，消费者照常。
   做法：以根本侧为准，第 k 章的偏移量 = 前 k−1 章 max(cs) 之和，根本侧改完就是
   1..N 单调递增——即「理想数据源」的样子；注释侧同一章用**同一个偏移量**。
4. **补丁按 VRI book 一个文件，但验收按 book_name。** 回绕修复必须两侧同一章同一偏移
   （只改一侧比不改更糟，前作 ad552c7ec 已实测）。一个 book_name 横跨多个 book
   （如 kn14 = 147、148 + 110–115、117），所以一个任务会改多份补丁；命令的检查报告
   必须按 book_name 汇总：改完后每本书内单调、注释侧的号都能在根本侧找到。
5. **补丁只是一张表，不是规则。** 一行一个段落，写这个段落最终的 book_name 与号；
   不支持「范围加偏移」「改写锚点原词」这类操作。好处是看表就知道结果、diff 一目了然；
   代价是回绕的书行数多（每章第 2 章起每段一行），这部分用 `--dump` 导出后批量生成。
6. **代价**（见 §4）：有回绕的书，cs_para 不再等于印本上的章内段号（kn12 第 2 章
   第 1 段可能变成 82）。插件 `note-context <book_name> <cs_para>` 手输段号、
   AI 注释的续跑游标会变（产物是句子号，不受影响）；另外重建本身会让约 5–10% 段落的 cs 值变化。

## 3. 设计

### 3.1 命令

```
php artisan upgrade:related.paragraph            # 全量重建
php artisan upgrade:related.paragraph --book=108 --book=145   # 只重建这几本（只删这几本）
php artisan upgrade:related.paragraph --check [--book=…]      # 只算不写，输出体检报告
php artisan upgrade:related.paragraph --dump --book=108       # 把该书重建结果（未套补丁）导出成补丁表格式，供编辑
```

每个 VRI book 的流程（同一事务内：删该 book 的行 → 批量插入）：

1. 段落全集取 `pali_texts`（523,284 段；wbw 少 7,171 段，前作新发现 5）。
2. 锚点取 `wbw_templates where type='.ctl.'`，排除页码标记，按 `(paragraph, wid)` 排序。
3. 解析 `para` 锚点（写法全表见下）；章标记 `xx_N`（`_0` 进序言 `xx_A`，`N>0` 退出序言）；
   书名标记 `xx`。
4. 定 book_name，优先级：锚点后缀 > 文件内当前章 / 书名标记 > **sn 书名表** > 空（P10）。
5. 段落继承上一个锚点；**遇 `book_titles.sn` 边界即停止继承**（P7）。
6. 套补丁：补丁表里有的段落，用补丁的值覆盖重建结果。
7. **有号没名字的段落把号清成 0**（不产生关联），并在检查报告里按 book 计数。放在补丁之后，
   这样补丁给了名字的段落不会被清掉。
8. 区间展开成多行；`book_id` 按 `book_titles` 定。
9. 检查（`--check` 只做这一步）：按 book_name 汇总回绕、孤儿号、根本缺号、
   无名但有号的段落、与现表差异段数；有回绕的 book_name 标红。

#### sn 书名表

`resources/data/related-paragraphs/book-names.csv`，两列 `sn,book_name`，一个真书（`book_titles.sn`，
一个 level-1）一行，只列需要的 sn。为什么按 sn 而不是按 VRI book：一个 VRI book 常含几部书，
各属不同 book_name（98 的五部义注分属 abhi3–7，200 / 201 / 203 / 177 同理），按 sn 正好一书一名。
初值从 `scripts/related/book_config.json` 的 segments 与旧 csv 的多数值生成，逐条人工过一遍。

sn 也解决不了的（一部书跨几个 book_name 且无后缀：202 Pācityādiyojanā、209 Vajirabuddhi-ṭīkā
跨 vin1–5），走补丁表逐段写名字。

#### `para` 锚点的全部写法（2026-11-25 全扫，命令必须全部兼容）

形式统一为 `para{号段}` 或 `para{号段}_{book_name}`。后缀共 47 种，全是
`an1–11 / dn1–3 / mn1–3 / sn1–5 / kn1–20 / vin1–5`。

| 号段写法 | 不带后缀 | 带后缀 | 例 | 解析为 begin–end |
| --- | ---: | ---: | --- | --- |
| 单号 `N` | 117,938 | 39,996 | `para5`、`para5_mn1` | N–N |
| 单号 `0` | （含在上行） | 54 | `para0_an10`（AN 各集首段） | 0：不产生关联，等同无号 |
| 单号带前导 0 | 2 | 2 | `para01`、`para01_mn1`（130@1551、192@1925） | 按整数 1；疑似笔误，补丁核对 |
| 完整区间 `N-M`，同位数 | 2,011 | 898 | `para23-25`、`para156-166_an10` | N–M |
| 完整区间，跨位数 | 81 | 24 | `para99-100`、`para308-1151_an5` | N–M（最大跨 844 号） |
| 缩写区间（M 位数少于 N） | 1,518 | 66 | `para292-3`、`para380-1_mn1` | M 补齐 N 的高位：292–293、380–381。全库没有补齐后 ≤ N 需要进位的情况 |
| 链式 `N-M-K` | 4 | 0 | `para18-19-20`、`para292-3-6`、`para266-7-8` | 取首尾，尾按缩写规则补齐：18–20、292–296、266–268 |
| 倒序（同位数，M < N） | 2 | 1 | `para504-407`、`para706-608` | 高位笔误：丢掉 M 的高位按缩写规则补齐，504–507、706–708 |
| 截断 `N-` | 1 | 0 | `para179-`（11@1577） | 解析不了：记日志，按单号 179 处理，补丁定 |

结构上的事实（解析器可以依赖）：

- 每个段落**最多一个**号段：有锚点的 121,557 段里，80,570 段只有不带后缀的一个，
  40,987 段是同号段的「不带后缀 + 带后缀」一对，**没有一段出现两个不同号段**。
- 锚点总在段首（首个锚点的 wid 全部 ≤ 5），所以「整段归这个号段」没有切分问题。
- 带后缀那个决定 book_name，不带后缀那个只提供号段。
- 表外的写法一律报错退出，不静默跳过——旧命令丢段就是静默空转造成的。

解析器可直接移植 `scripts/related/lib/MarkerParser.php`（已全库验证），放 `App\Services\`
（纯能力，与请求无关）。命令落地后 `scripts/related/` 删除。

### 3.2 补丁文件

位置：`api-v13/resources/data/related-paragraphs/{book}.csv`，每个 VRI book 一个，
没有补丁的 book 就没有文件。格式与 cs6_para.csv 相同，去掉 book 列（文件名就是 book）：

```csv
para,book_name,begin,end
1551,mn1,147,147
1552,mn1,147,147
697,kn12,82,82
698,kn12,82,83
1215,vin6,1,1
```

- 一行一个段落，写的是该段落的**最终值**，覆盖重建结果；重建结果里该段没有号的，就是增加。
- `begin`–`end` 是区间，展开成多行，与重建结果同一规则。
- `book_name` 留空 = 沿用重建出的 book_name，只改号。
- 理由不进表，写在提交信息或本文的任务单里。
- wbw_templates 与 pali_texts 的段落号是固定的，补丁直接按 `(book, para)` 坐标写，不需要防坐标漂移的校验。
- 检查报告会列出「补丁值与重建值相同」的行（多余，可删），以及补丁里不存在于 pali_texts 的段落（报错）。

### 3.3 不变的东西

- 表结构不动，不加列（回绕改 cs_para 解决，不加 segment 列）。
- book_name 不改名，不出现章后缀。
- v2 接口代码不动，只改数据；响应形状不变，v4 照常工作，只是查到的结果变对了
  （v4 与 v6 共用这张表）。
